CEO 리뷰에서 1차안(포트레이트를 아예 없앤 순수 데이터 패널)이 "캐릭터 아트가 없다"는 이유로 반려되어, 기존 적 포트레이트(art-direction.md §5)의 프레임+실루엣 기법을 재사용한 원형 초상을 .opponent-identity 안, 이름 옆에 작게 배치했다(64px — 상단 바가 이미 조밀해서 §5의 96px 몬스터 포트레이트처럼 화면 중앙을 크게 차지하는 구성은 쓰지 않았다). 아래 배틀 화면 두 상태에 쓰인 심볼은 rev.4(목/어깨 비례를 다시 잡은 플랫/셀셰이딩 실루엣, 실제 64px에서 가독성 확인 완료) — rev.2/rev.3과의 비교는 이 문서 하단 "asset: 상대 포트레이트" 섹션 참고. 손패는 카드 뒷면 3장을 겹쳐 쌓은 .hand-count-stack + 숫자로 "매수만" 표시. HP바/마나 방울/덱·버림더미 배지는 전부 기존 컴포넌트 그대로 재사용(신규 CSS 없음). 내 턴이 아닐 때는 손패 카드에 기존 .unaffordable 스타일(45% 불투명, 클릭 무반응)을 재사용해 "선택 불가"를 표시하고 화면 상단에 "상대 턴" 라벨이 뜬다(spec §7.2) — 기존 .card.unaffordable은 마나 부족 표시 용도였지만 "지금 이 카드를 낼 수 없다"는 의미 자체는 동일하므로 새 클래스를 만들지 않고 재사용했다.

asset: 상대 포트레이트 — rev.2(플랫 픽토그램) vs. rev.3(그라디언트 일러스트, superseded) vs. rev.4(플랫/셀셰이딩, 현재 반영본) (art-direction.md §8.5)

CEO 리뷰가 두 번 뒤집혔다. 1차 피드백("이런 픽토그램 말고 그래픽으로 만들어줘")에 rev.3(그라디언트+레이어드 셰이딩 일러스트)으로 답했으나, 이후 방향이 다시 정리됐다: 팀 제약(SVG/프로시저럴, AI 이미지 생성 안 씀)은 유지하고, 픽토그램 스타일 자체는 문제가 아니었다 — 진짜 문제는 실제 게임 내 크기(64px)에서의 가독성이었다. 헤드리스 브라우저로 64px 실측 스크린샷 비교를 해보니:

  • rev.2는 사실 64px에서도 "사람"으로 또렷하게 읽혔다 — 다만 목도 어깨도 없이 원형 머리가 종 모양 몸통 위에 바로 얹힌 실루엣이라, 모든 OS/앱의 "계정 없음" 기본 아바타 아이콘과 완전히 같은 모양이었다. 모호해서 못 읽은 게 아니라, "사람"으로는 읽히되 "게임 캐릭터"가 아니라 "시스템 UI 아이콘"으로 읽힌 것 — 애초 CEO 피드백의 실체에 더 가깝다.
  • rev.3의 그라디언트/림라이트 스트로크/헤어 광택선은 104px 쇼케이스에서는 잘 보이지만 64px 실측에서는 확연히 뭉개졌다 — 머리는 입체감 있는 구체가 아니라 부드러운 빛 얼룩처럼 보였고, 얇은 스트로크 디테일은 거의 사라졌다. "104px에서 좋아 보이는 그라디언트가 64px에서는 얼룩이 될 수 있다"는 우려가 실측으로 확인됐다.

rev.4는 두 문제를 각각 다른 방식으로 고쳤다: 실루엣 자체를 목이 뚜렷하고(머리보다 확실히 좁음) 어깨가 가장 넓은 지점이며 허리 쪽으로 다시 좁아지는 실제 인체 비례로 다시 그렸다(rev.2/rev.3처럼 아래로 갈수록 계속 넓어지는 종 모양이 아님) — 이걸로 "계정 아이콘"으로 오독되는 문제를 없앴다. 셰이딩은 그라디언트 대신 단단한 경계의 2톤 셀셰이딩(정중선 기준 밝은 면/어두운 면 분할, opp4-body/ opp4-body-shadow/opp4-head-grad)으로 바꿔 입체감은 유지하되 축소해도 무너지지 않게 했다 — 하드 엣지는 그라디언트처럼 다운스케일에서 흐려지지 않는다. 머리카락도 광택 스트로크를 빼고 대비가 강한 단색 3번째 톤 하나로만 표현해, 실루엣 윤곽 자체(변형마다 다른 헤어라인)가 디테일이 아니라 "정보"를 전달하게 했다 — 미세 표면 디테일보다 실루엣이 축소 내구성이 훨씬 좋기 때문. 아래 비교는 왼쪽부터 rev.2 → rev.3 → rev.4이고, 각 열에 실제 게임 내 크기(64px)와 쇼케이스 크기(104px)를 모두 보여준다.

실제 게임 내 크기(64px, .opponent-portrait-frame)는 rev.2부터 계속 안 바꿨다 — .opponent-identity 가로줄이 이미 조밀해서 나온 레이아웃 제약이지 아트 판단이 아니고, rev.4는 바로 이 64px 크기에서 헤드리스 스크린샷으로 가독성을 확인한 뒤 반영했다(위 배틀 화면 두 상태의 상대 포트레이트가 실제 64px 크기). 위 비교의 104px 스와치는 104px(.opponent-portrait-frame.showcase, 이 목업 리뷰 전용 modifier — 게임 화면에는 안 씀)로 키워서 디테일을 보기 쉽게 한 것일 뿐, 판단 기준은 항상 64px 열이다. 3개 변형 모두 같은 프레임(원형, --steel 테두리)과 같은 몸통/머리 기반 shape — 헤어라인 디테일만 다르게 그려서 "동일 계열의 다른 스타일"로 읽히게 했다(개별 캐릭터가 아니라 하나의 제네릭 피규어의 3가지 겉모습이라는 인상, rev.2/rev.3과 동일한 의도). 몬스터 실루엣 (art-direction.md §5)과 달리 투구 슬릿·후드 그림자 같은 얼굴 컷아웃은 여전히 넣지 않았다 — 컷아웃은 "가면/정체를 가림"이라는 몬스터·도적 계열 코드라서, 사람을 나타낼 때는 오히려 안 쓰는 쪽이 더 중립적이다. 계정 아바타 시스템이 이번 마일스톤 스코프 밖(spec §4.4)이라 특정 계정에 묶이지 않는 순수 장식 요소이고, 세 변형 중 무엇을 보여줄지는 매치마다(예: 방 코드로 시드한) 의사난수로 고르는 것을 제안한다 — 선택 로직 자체는 게임 로직이므로 프로그래머 담당(Phase 4.7).
