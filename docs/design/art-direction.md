# ARCANE LEDGER — 아트 디렉션

기획안(`gdd-arcane-ledger.md`) 섹션 9의 비주얼 스타일을 프로그래머가 그대로 구현할 수 있는 정확한 수치/에셋으로 확정한다.

## 1. 컬러 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#150f1a` | 배경 (짙은 자두빛 잉크) |
| `--bg-raised` | `#1e1624` | 카드/패널 배경 |
| `--bg-inset` | `#120c17` | 오목한 영역 (덱/버림더미 카운터 등) |
| `--line` | `rgba(242,233,216,0.14)` | 테두리/구분선 |
| `--ink` | `#f2e9d8` | 본문 텍스트, 카드 프레임 |
| `--ink-dim` | `#b8a99a` | 보조 텍스트 (카드 효과 설명) |
| `--ink-faint` | `#6f6258` | 레이블/캡션 |
| `--crimson` | `#c23b4c` | Attack 카드, 공격 의도 |
| `--steel` | `#3f8fa6` | Skill 카드, 방어 의도 |
| `--gold` | `#d4af37` | Power 카드, 보스/강조 |

## 2. 타이포그래피

- 카드명·섹션 타이틀: 세리프 — `Georgia, "Iowan Old Style", "Palatino Linotype", "Noto Serif KR", serif`
- 본문/UI 텍스트: 시스템 산세리프 — `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`
- 숫자(HP/마나/데미지): 모노스페이스, `font-variant-numeric: tabular-nums`

## 3. 카드 스펙

- 크기: **132×184px** (비율 약 0.72, 표준 카드 비율)
- 모서리 반경: **8px**
- 테두리: 1px, `--line`
- 상단 타입 컬러 바: 높이 **4px** (Attack=crimson / Skill=steel / Power=gold)
- 코스트 배지: 지름 **22px** 원, 카드 좌상단에 절반 걸치도록 배치, 배경은 타입 컬러, 텍스트는 `--bg`
- 내부 패딩: 10px
- 카드명: 13px 세리프 bold
- 효과 텍스트: 11.5px 산세리프, `--ink-dim`, 하단 정렬

## 4. 아이콘 세트

`assets/icons.svg`에 스프라이트 시트로 저장 (24×24 viewBox, stroke 기반, `currentColor` 상속 — 사용처 색상에 맞게 자동 채색됨). 사용: `<use href="assets/icons.svg#icon-sword" />`

| 아이콘 | ID | 용도 |
|---|---|---|
| 검 | `icon-sword` | 공격 의도, Attack 타입 표시 |
| 방패 | `icon-shield` | 방어 의도/방어도, Skill 타입 표시 |
| 왕관 | `icon-crown` | 보스 표시, Power 타입 표시 |
| 마나 방울 | `icon-mana` | 마나 게이지 |
| 해골 | `icon-skull` | 처치/즉사 위협 경고 (선택적 사용) |
| 하트 | `icon-heart` | 플레이어 HP |

일러스트 없이 기하학적 심볼로만 구성 — 팀 아트 제약(SVG/프로시저럴)을 그대로 반영.

## 5. 적 포트레이트 (프레임 + 캐릭터 실루엣)

단색 도형만으로는 캐릭터감이 부족하다는 피드백에 따라, **프레임(도형) + 안에 든 캐릭터 실루엣** 2겹 구조로 변경했다. 실루엣은 여전히 손그림/AI 생성 없이 벡터 path로만 구성하되, 투구·후드·왕관 등 형태적 특징으로 캐릭터성을 표현한다.

| 적 | 프레임 도형 | 실루엣 심볼 | 특징 |
|---|---|---|---|
| 녹슨 파수병 | 정육각형 (outline) | `icon-char-sentinel` | 각진 투구 + 좁은 시야 슬릿(컷아웃) + 넓은 어깨 갑옷 |
| 그림자 도적 | 다이아몬드 (outline, 45° 회전) | `icon-char-thief` | 뾰족한 후드 + 그림자 진 얼굴(다이아몬드 컷아웃) + 좁은 어깨 |
| 폐허의 심판관 (보스) | 대형 정육각형 (outline, gold) | `icon-char-boss` | 왕관형 상단 지그재그 + 해진 로브 하단 지그재그 + 넓은 실루엣 |

- 프레임: outline만 사용 (배경은 `--bg-raised`, 테두리 2px `--crimson`/일반, `--gold`/보스) — 도형 자체는 배지 역할만 하고 시각적 무게는 안쪽 실루엣이 가진다.
- 실루엣: `viewBox 0 0 100 100`, `fill-rule="evenodd"`로 얼굴/시야 부분을 배경색 컷아웃 처리, `currentColor`로 프레임과 동일 색 상속.
- 프레임 크기: 96×96px (일반), 120×120px (보스). 실루엣은 프레임의 약 70% 크기로 중앙 배치.
- `assets/icons.svg`에 `icon-char-sentinel`, `icon-char-thief`, `icon-char-boss` 심볼로 저장.

## 6. 배틀 화면 레이아웃

- **적 영역** (상단 중앙): 포트레이트 → HP 바 → 의도 배지(아이콘+예상 수치, 포트레이트 위에 말풍선처럼 배치)
- **플레이어 정보** (좌하단): 하트 아이콘+HP, 방패 아이콘+방어도(0이면 숨김)
- **마나 게이지** (플레이어 정보 옆): 마나 방울 아이콘 3개, 소모분은 outline만 남기고 채움 해제
- **손패** (하단 중앙): 카드 최대 5장, 살짝 부채꼴 또는 균등 간격 가로 배열
- **덱/버림더미 카운터** (우하단): 작은 숫자 배지 2개

실제 목업은 아래 링크 참고 — 이 문서의 수치를 그대로 시각화한 것.

## 7. 표면 디테일 (평면감 방지)

1차 목업이 "날것" 같다는 피드백에 따라 추가한 마감 규칙. 색만 칠한 평면이 아니라 재질감이 느껴지도록 한다.

- **배경 그레인**: 전투 화면 배경에 미세한 노이즈 텍스처를 `background-blend-mode: overlay`로 얹는다 (SVG `feTurbulence` 기반, 알파 0.05 수준 — 육안으로 "약간 거친 종이" 느낌만 나는 정도).
- **적 포트레이트**: 프레임 안쪽에 방사형 그라디언트(중심 밝게, 가장자리 `--bg-raised`)로 입체감을 주고, `box-shadow` 이중 사용(외부 glow + 내부 vignette)으로 깊이를 만든다. 은은한 pulse 애니메이션(3.6초 주기)으로 생동감 부여 — `prefers-reduced-motion` 존중.
- **카드**: 상단에 옅은 하이라이트 그라디언트(종이가 빛을 받는 느낌), 아이콘은 원형 컬러 칩 배경 위에 배치, 효과 텍스트는 위쪽에 점선 구분선으로 "일러스트 영역 / 텍스트 박스" 분리, 카드 전체에 elevation 그림자(`box-shadow` 다중 레이어)로 테이블 위에 놓인 느낌.
- **코스트 배지**: 단색 원이 아니라 방사형 그라디언트로 하이라이트를 주어 보석/코인 같은 질감.
- **HP 바**: 단색 대신 그라디언트 + 상단 하이라이트 라인으로 유리관 같은 입체감.
- **마나 방울**: 활성 상태에 `drop-shadow` 글로우를 줘서 "차 있음"이 실제로 빛나 보이게.

이 규칙들은 전부 순수 CSS(그라디언트/그림자/블렌드 모드)로 구현 가능 — 별도 텍스처 이미지 에셋이 필요 없다.

## 8. 온라인 PvP 확장 비주얼

`spec-online-pvp.md` §9가 남긴 아트 부채(로그인, 덱 관리, 상대 플레이어 패널, 카드 뒷면, 로비/전적 화면)에
대한 답. 목업 파일: `assets/mockups/screen-{login,deck-slots,deck-editor,lobby,battle-pvp,match-history}.html`
(각 파일에 `../../css/style.css` + `assets/mockups/pvp-components.css`를 로드해 브라우저로 바로 열어 확인
가능 — 상태별로 여러 변형을 한 페이지에 나열한 리뷰용 스펙 시트다). 신규 컴포넌트 CSS는 전부
`assets/mockups/pvp-components.css` 한 파일에 있으며, 프로그래머가 4.1/4.5/4.7/5.1 단계에서 `css/style.css`로
그대로 옮겨 쓸 수 있도록 정리했다. 새 색상 토큰은 추가하지 않았다 — §1의 팔레트만으로 전부 구성.

### 8.1 로그인/회원가입 (spec §4.1-§4.2)

기존 `.overlay-panel` 구조를 재사용한 단일 패널에 로그인/회원가입 탭(`.auth-tabs`)을 얹는 구성 — 별도 화면
전환이 아니라 탭 전환. 필드는 `.field-input`(아이콘 + 인풋, 포커스 시 gold 테두리, 에러 시 crimson 테두리)
+ 필드별 인라인 에러(`.field-error`, crimson, `icon-warning` 동반). 신규 아이콘 `icon-mail`/`icon-lock`을
`assets/icons.svg`에 추가. 하단에 "플레이 방법 보기" 링크(spec §4.3 — How to Play는 비로그인도 접근 가능).

### 8.2 덱 관리 — 슬롯 목록 (spec §5.4, plan 3.3)

슬롯은 카드 프레임이 아니라 별도 패널 컴포넌트(`.deck-slot-tile`, 236×172px)로 설계했다 — 슬롯은 "카드"가
아니라 "덱 전체를 가리키는 타일"이므로 132×184 카드 프레임을 억지로 재사용하지 않았다. 20장 미만 슬롯은
`.badge-incomplete`(crimson 칩, "미완성") 배지가 타일 우상단에 붙는다. 빈 슬롯은 점선 테두리
`.deck-slot-tile.empty` + "+ 새 덱 만들기" 플레이스홀더.

### 8.3 덱 관리 — 에디터 (spec §5.5, plan 3.3)

**풀 그리드**(브라우징 영역): 기존 132×184 카드 프레임을 82% 스케일로 그대로 재사용, 신규 카드 비주얼
언어를 만들지 않는다는 spec 요구를 그대로 따랐다. 매수 배지(`n/3`)는 카드 카운트가 아니라 UI 오버레이이므로
카드 우상단 모서리에 배치(코스트 배지와 대칭) — 카드 하단에 두면 Power 카드처럼 효과 텍스트가 긴 카드에서
겹침이 발생해 상단으로 옮겼다. 3/3 도달 시 배지가 타입 컬러로 꽉 차고(`.pool-count-badge.full`) 카드가 기존
`.unaffordable` 패턴(45% 불투명)으로 비활성화.

**이 덱 목록**(구성 결과 영역): 카드 그리드가 아니라 조밀한 리스트 행(`.deck-list-row` — 코스트 칩 + 이름 +
매수 + `−` 버튼)으로 완전히 다른 실루엣을 사용 — "지금 보고 있는 것"과 "지금까지 고른 것"이 레이아웃
문법 자체로 구분되어야 한다는 spec 요구를 그리드 vs. 리스트로 만족.

덱 카운터(`.deck-counter`)는 20장 미만이면 `.invalid`(crimson)로 전환 + 하단에 "최소 20장이 필요합니다"
문구.

### 8.4 로비 / 방 코드 / 대기 / 접속 끊김 (spec §6.2, §8.2, plan 4.10)

방 코드는 `.lobby-code`(모노스페이스, 큰 자간, gold, 인셋 박스) + `.btn-copy`(신규 `icon-copy`). 대기 상태는
순수 CSS 스피너(`.spinner`, 이 화면 전용 신규 애니메이션 — art-direction 기존 pulse와는 별개의 로딩 인디케이터
패턴). 접속 끊김 배너(`.disconnect-overlay` / `.disconnect-banner`)는 보드 상태 위에 반투명 오버레이로 뜨고,
"기권승 처리하기" 버튼은 10초 미만일 때 비활성 스타일(opacity 낮춤), 10초 경과 후 crimson 강조로 활성화되는
두 상태를 목업에 모두 포함. 신규 `icon-warning` 추가.

### 8.5 배틀 화면 — 상대 플레이어 패널 (spec §7.2, plan 4.9)

**rev.2 (CEO 리뷰 반영)**: 1차안은 기존 적 포트레이트+실루엣+의도 배지(§5-6)를 완전히 제거하고 순수 데이터
패널(이름 → HP바 → 방어도/마나/손패매수/덱·버림더미)로 갔었다 — §8.8에 열린 결정으로 플래그했던 부분인데,
CEO 확인 결과 "상대 패널에 캐릭터 아트가 있어야 한다, 데이터 패널만으로는 부족하다"는 결정이 내려와 뒤집혔다.

이번 마일스톤에는 계정 아바타/프로필 커스터마이징이 없으므로(spec §4.4) "상대가 고른 아바타"도 "상대의
캐릭터 클래스" 같은 것도 표시할 수 없다 — 대신 **"일반적인 상대 한 명"을 나타내는 순수 장식용 제네릭
실루엣**을 넣기로 했다. §5의 프레임(도형 배지)+실루엣(안쪽 캐릭터) 2겹 기법을 그대로 재사용하되, 몬스터가
아니라 사람으로 읽히도록 다음을 바꿨다:

- **프레임 도형**: 육각형/다이아몬드(몬스터 배지 모양) 대신 **원형** — "초상 사진" 쪽에 가까운 중립적 형태.
- **프레임 색**: `--crimson`/`--gold`(이 팔레트에서 이미 "적대적 몬스터"/"보스" 신호로 쓰이고 있음) 대신
  `--steel` — PvP 상대는 위협으로 코드화된 몬스터가 아니라 그냥 사람이라는 것을 색으로도 구분.
- **실루엣**: 투구 슬릿(파수병)이나 그림자 진 얼굴(도적) 같은 얼굴 컷아웃을 넣지 않았다 — 그 컷아웃들은
  "가면 뒤에 숨은 존재"라는 몬스터/도적 계열의 코드라서, 평범한 사람을 나타낼 때는 오히려 없는 쪽이 중립적.
  대신 머리+어깨만 있는 단순한 인물 흉상 실루엣(`icon-char-opponent-a/b/c`, `assets/icons.svg`)을 썼다.
- **크기**: 96px(몬스터, §5) 대신 64px — 상대 패널이 이미 이름/HP바/메타 정보로 조밀한 가로형 레이아웃이라
  화면 중앙을 크게 차지하는 §6식 배치를 그대로 쓰지 않고, `.opponent-identity` 안에 이름 옆 작은 초상으로
  넣었다.

**변형 3종, 매치당 의사난수 선택**: 완전히 동일한 실루엣 1종만 쓰면 모든 매치가 시각적으로 100% 동일해
보이는데, 이건 그 자체로 문제라기보다(상대는 실제로 익명이니 매치마다 달라 보일 "이유"가 없다) 그래도 화면에
생기를 조금 주는 게 낫다고 판단해 헤어라인만 다른 3개 변형(`icon-char-opponent-a`=짧은 머리,
`-b`=볼륨 있는 머리, `-c`=어깨까지 오는 긴 머리)을 만들었다. 세 변형 모두 같은 몸통 실루엣을 공유해서
"서로 다른 캐릭터"가 아니라 "하나의 제네릭 피규어의 다른 겉모습"으로 읽히게 의도했다. **계정/전적과
무관하게 완전히 무의미한 장식** — 승패, 랭크, 스킨 소유 여부 등 어떤 것도 나타내지 않는다. 선택 로직(예:
방 코드나 매치 ID로 시드해서 한 매치 동안은 고정되게)은 게임 로직이므로 프로그래머 담당(Phase 4.7) — 이
문서는 "3개 중 하나를 보여준다"까지만 규정한다.

HP바/마나 방울/덱·버림더미 배지는 전부 기존 컴포넌트를 그대로 재사용(신규 CSS 없음). 상대 손패는 매수만
공개(spec §7.2)하므로 카드 뒷면 3장을 겹쳐 쌓은 `.hand-count-stack` + 숫자로 표시.

**턴 타이머(spec §7.3)**: 활성 플레이어당 하나뿐인 공유 카운트다운이다 — 양쪽 화면에 동시에 서로 다른
숫자가 떠 있는 두 개의 시계가 아니다. 타이머 배지(`.turn-timer`)는 항상 "지금 행동 중인 쪽의 컨트롤 옆"에
붙어 위치가 바뀐다: 내 턴이면 하단 End Turn 버튼 옆, 상대 턴이면 상단 상대 패널 안. 상대 턴일 때는 화면
상단에 `.turn-status`("상대 턴") 라벨이 추가로 뜨고(spec §7.2), 내 손패 카드는 기존 `.unaffordable`
스타일로 비활성화된다(마나 부족 표시와 같은 클래스를 재사용 — "지금 낼 수 없다"는 의미 자체는 동일하므로
새 클래스를 만들지 않았다).

10초 이하 pulse는 §7의 `portrait-pulse`와 같은 기법(이중 `box-shadow` 키프레임 + `prefers-reduced-motion`
가드)을 재사용하되, 주기는 3.6초가 아니라 **1초**로 훨씬 급박하게 튜닝했다 — 3.6초는 "포트레이트가
살아있는 느낌"을 위한 값이고, 이건 "시간이 얼마 안 남았다"는 경고 신호가 목적이라 같은 패턴을 다른 목적에
맞게 재조정했다. 정확한 주기값은 확정이 아니라 제안 — 기획 컨펌 대상.

### 8.6 카드 뒷면 (spec §7.2, plan 4.9)

`assets/icons.svg#card-back` (132×184, 카드 프레임과 동일 크기). 골드 테두리로 카드 앞면(테두리는 흐린
`--line`, 유색인 곳은 상단 타입 바뿐)과 한눈에 구분되도록 했다. 중앙 마나 방울 모티프(`icon-mana` 확대) +
대각선 방사 장식 + 모서리 다이아몬드로 "장부/마나" 정체성을 일러스트 없이 기하학적 요소로만 표현 — §4의
아이콘 세트 제약을 그대로 따름.

### 8.7 전적 화면 (spec §6.5, plan 5.2)

상단 승/패 집계(`.history-stat`)는 큰 숫자 두 개 — 승=gold, 패=crimson(기존 승리/패배 화면 색 관례 재사용)
— 를 얇은 구분선으로만 나눠 "리스트에서 파생된 요약"임을 시각적으로도 드러냈다. 각 행은 결과 칩
(`.result-chip.win`/`.loss`) + 상대 표시 이름 + 날짜. 기권승은 새 색을 추가하지 않고 같은 gold 칩에
`(기권)` 텍스트 라벨만 덧붙이는 것으로 구분했다(팔레트에 3번째 결과색을 넣지 않기 위한 선택).

### 8.8 열린 결정 사항 (기획/CEO 확인 요청)

이 섹션에서 스펙이 명시하지 않아 아티스트가 임의로 정한 것 — 확정 전까지는 제안으로 취급:

- **8.5의 상대 포트레이트 변형 개수(3종)와 선택 방식(매치 ID/방 코드 시드 의사난수)은 제안이지, 확정된
  스펙이 아니다**. "포트레이트가 있어야 한다"는 CEO 결정은 명확하지만, 몇 종을 만들지·매치마다 고정할지
  매번 랜덤할지는 아무도 규정한 적이 없어 아티스트가 임의로 정했다. 특히 "매치 ID로 시드해서 그 매치 동안은
  고정"이라는 부분은 순전히 UX 직관(같은 매치 안에서 상대 초상이 턴마다 바뀌면 이상해 보일 것 같다)으로
  제안한 것이라 프로그래머/기획 컨펌 필요.
- **8.5의 턴 타이머 pulse 주기(1초)**는 art-direction.md 기존 pulse의 리터럴 재사용이 아니라 튜닝값 — 확정
  아님.
