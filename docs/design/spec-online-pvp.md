# ARCANE LEDGER — 온라인 1:1 PvP 스펙

`docs/design/online-pvp-plan.md`(프로듀서 작업 분해, Phase 0 오픈 퀘스천 0.1~0.7)에 대한 CEO 확정 답변을
실제 구현 가능한 스펙으로 옮긴 문서. 프로그래머는 이 문서 + 기존 `gdd-arcane-ledger.md`(카드 효과/수치)
+ `art-direction.md`(시각 언어)만으로 게임 로직/화면을 구현할 수 있어야 한다.

네트워킹 아키텍처(서버 기술, 호스팅, 와이어 프로토콜)와 계정/덱/전적을 저장할 서버 데이터 저장소(DB
종류, 스키마 등)는 이 문서의 범위 밖 — `online-pvp-plan.md` Phase 1의 프로그래머 재량. 이 문서는
**무엇이 화면에 보여야 하고 어떤 규칙으로 판정되어야 하는가**만 정의한다.

---

## 1. 개요 — CEO 확정 사항

| # | 결정 |
|---|---|
| 1 | vs-AI 모드 완전 삭제. 온라인 1:1 PvP가 유일한 모드 — 모드 선택 화면 없음 |
| 2 | PvP는 독립된 단판 전투 — 기존 던전 런 구조(전투3+보상+휴식+보스)는 유지하지 않고 대체됨 |
| 3 | 덱 에디터의 카드 풀은 시작부터 전부 오픈 — 언락/재화 시스템 없음 |
| 4 | 턴 타이머 24초 — 타임아웃 시 동작을 이 문서에서 명시 (§7.3) |
| 5 | 접속 끊김: 유예 시간 후 기권 처리 — 정확한 유예 시간을 이 문서에서 확정 (§8) |
| 6 | **로그인은 이메일/비밀번호를 직접 구현** (소셜/OAuth 없음) — 계정이 필수이며 게스트 모드 없음 (§4) |
| 7 | **전적은 승/패 기록만 제공** — ELO/레이팅/랭킹 없음 (§6.5) |
| 8 | **덱은 계정당 최대 3개까지 저장**, 매치 큐 진입(로비) 전에 그중 하나를 선택 (§5, §6.1) |

## 2. 명시적으로 제거/대체되는 것

아래는 기존 문서의 해당 절이 PvP 전용 체제에서는 더 이상 적용되지 않음을 명시한다. 하위 작업자가 옛 문서와
이 문서 사이에서 헷갈리지 않도록 여기 모아둔다.

| 제거 대상 | 근거 문서 | 비고 |
|---|---|---|
| vs-컴퓨터 모드, 모드 선택 화면 | — (신규 예정이었으나 무산) | 진입점은 PvP 하나뿐. `screen-start`에 모드 선택 UI 불필요 |
| 적(enemy) 스크립트 패턴 시스템 (`ENEMY_DEFS`, `pattern`) | `gdd-arcane-ledger.md` §7 | 상대는 실제 플레이어 — 고정 패턴 없음 |
| 의도(intent) 예고 아이콘 | `gdd-arcane-ledger.md` §5, `onboarding.md` §2-4 | 실제 상대는 다음 행동을 예고할 수 없음(진짜 선택을 함). **후속 조치 필요**: `onboarding.md`의 "의도 아이콘" 설명(§2 항목 4)은 PvP 체제와 맞지 않으므로 별도 개정이 필요 — 이 스펙에서 새로 다루지 않으며, 다음 기획 작업으로 플래그만 남긴다 |
| 던전 런 구조 (`ROOM_SEQUENCE`: 전투3+보상+휴식+보스) | `gdd-arcane-ledger.md` §8 | 매치 = 단판 전투 하나. 방 이동 개념 없음 |
| 전투 승리 시 보상 카드 3택1 화면 | `gdd-arcane-ledger.md` §6.2, §8 | `REWARD_POOL`은 보상이 아니라 덱 에디터의 카드 풀 소스로 용도가 바뀜 (§5.1) |
| 휴식 화면 (`REST_HEAL_RATIO` 30% 회복) | `gdd-arcane-ledger.md` §8 | 단판이므로 휴식 개념 자체가 없음 |
| 파워 카드의 "런 동안 영구" 표현 | `gdd-arcane-ledger.md` §6.2 | 용어만 정정: "런" → "이번 매치". 수치/동작은 변경 없음 |
| ~~"별도 전적/통계 저장 없음 — 스코프 밖"~~ (구버전 §5.4) | 이 문서 구버전 | **철회됨.** CEO 요구사항 변경으로 승/패 전적 저장이 이제 스코프 안에 포함된다 — §6.5 참고. 더 이상 유효한 컷 항목이 아니므로 하위 작업자는 옛 판단을 참조하지 말 것 |

계정 도입에 따른 추가 컷 항목(비밀번호 재설정, 이메일 인증 등)은 §4.4에 별도로 정리했다 — 이 표는 원래
"vs-AI/던전 런 → PvP 전환"에 따른 컷만 다루므로 계정 관련 컷은 성격이 달라 섞지 않는다.

## 3. 화면 흐름 개요

```
(비로그인) 로그인 / 회원가입 화면 (§4)
   └─ 로그인 성공 → 메인 메뉴

메인 메뉴 (덱 관리 / 전적 / 플레이, 표시 이름 + 로그아웃 상시 노출)
   ├─ 덱 관리 화면 — 슬롯 목록 → 슬롯 편집(덱 에디터) (§5)
   ├─ 전적 화면 (§6.5)
   └─ 플레이 → 덱 선택 화면 (저장된 유효 덱 중 하나 선택, §6.1)
                 → 로비 (방 생성 / 참가) (§6.2)
                 → 대기 화면 (상대 접속 대기)
                 → 매치 시작 시퀀스 (§6.3)
                 → 배틀 화면 (양쪽 플레이어 상태, §7)
                 → 매치 종료 화면 (승/패/기권승, 전적 자동 기록) (§6.4)
                 → 다시 플레이 → 덱 선택 화면으로 복귀 / 메인 메뉴
```

How to Play(`screen-howto`) 화면은 유지하되, 의도 아이콘 설명 절은 §2에서 플래그한 대로 별도 개정
대상. **How to Play는 예외적으로 비로그인 상태에서도 접근 가능** — 계정/저장 데이터와 무관한 정적
설명 화면이므로 로그인 화면에 "플레이 방법 보기" 링크로 노출한다 (§4.3).

## 4. 계정 (인증)

계정이 도입되면서 덱 저장(§5)과 전적(§6.5)이 모두 계정에 종속된다. 이 절은 회원가입/로그인/비로그인
방문자가 보는 것만 정의한다 — 세션 토큰 방식, 비밀번호 해싱, DB 스키마 등 서버 구현은 프로그래머 재량.

### 4.1 회원가입

입력 필드는 세 가지:

| 필드 | 규칙 | 비고 |
|---|---|---|
| 이메일 | 표준 이메일 형식 검증(클라이언트) + 서버측 중복 체크 | 로그인 식별자로만 쓰인다. **상대 플레이어에게 어디서도 노출되지 않음**(로비, 배틀 화면, 전적 화면 어디에도 이메일 표시 없음) — 상대에게는 항상 표시 이름만 보인다 |
| 비밀번호 | 최소 8자, 그 외 복잡도(특수문자/대소문자 조합 등) 강제 없음 | 작은 팀 MVP에서 가입 마찰을 최소화하는 쪽을 택함. "비밀번호 확인" 입력 필드를 함께 받아 두 값이 다르면 인라인 에러 |
| 표시 이름(닉네임) | 필수, 2~16자 | 상대에게 보이는 유일한 식별자. **계정 간 중복 허용**(고유성 강제 안 함) — 표시 이름은 로그인 식별자가 아니라 화면 표시용이므로 중복돼도 게임 로직에 영향 없음. 가입 시 1회 설정 후 변경 UI는 이번 스코프에 없음(§4.4) |

- 이메일이 이미 가입되어 있으면 "이미 사용 중인 이메일입니다" 인라인 에러, 입력값은 유지.
- 검증 실패(형식 오류, 8자 미만, 비밀번호 불일치, 표시 이름 길이 초과 등) 시 해당 필드 아래 인라인
  에러 메시지, 나머지 입력값은 유지.
- 가입 성공 시 **자동으로 로그인 처리되어 메인 메뉴로 이동** — 별도의 "가입 완료, 다시 로그인하세요"
  단계 없음 (마찰 최소화).
- 신규 계정의 초기 상태(저장된 덱 0개로 시작할지, 기본 덱을 미리 채워줄지)는 §5.4에서 확정.

### 4.2 로그인

- 입력 필드: 이메일 + 비밀번호.
- 실패 시 문구는 **하나로 통일**: "이메일 또는 비밀번호가 올바르지 않습니다" — 이메일이 존재하지
  않는 경우와 비밀번호가 틀린 경우를 구분해서 알려주지 않는다 (계정 존재 여부를 외부에 노출하지 않는
  기본적인 방어).
- 로그인 성공 시 메인 메뉴로 이동.
- 세션 유지 방식(브라우저를 껐다 켰을 때 재로그인 없이 이어지는지 등)은 프로그래머 재량 — 이 문서는
  "로그인 성공 후에는 로그아웃 전까지 별도 재인증 없이 덱 관리/전적/플레이에 접근 가능해야 한다"는
  동작만 규정한다.
- **로그아웃**: 메인 메뉴 상단에 표시 이름 옆에 "로그아웃" 버튼 상시 노출. 클릭 시 확인창 없이 즉시
  로그아웃 후 로그인 화면으로 이동. **배틀 화면에는 계정 관련 UI(로그아웃 버튼 포함)를 노출하지
  않는다** — 매치 도중 실수로 로그아웃해 접속이 끊기는 상황을 UI 단에서 원천 차단.

### 4.3 비로그인 방문자가 볼 수 있는 것

**게스트 모드는 없다.** 계정 없이는 덱 관리/전적/플레이 어디에도 접근할 수 없다.

- 최초 진입(비로그인 상태)에서 보이는 화면은 로그인/회원가입 화면뿐 — "로그인" / "회원가입" 두 탭을
  전환하는 하나의 화면으로 구현할 것을 권장(정확한 레이아웃은 프로그래머/아티스트 재량, 이 문서는
  접근 가능 여부만 규정).
- 유일한 예외는 How to Play(§3) — 계정/저장 데이터와 무관한 정적 설명 화면이라 로그인 없이도 열람 가능.
- **게스트로 플레이한 뒤 나중에 계정을 연결하는 마이그레이션 흐름은 만들지 않는다** — 처음부터 계정을
  필수로 요구하면 "계정 없는 판이 전적에 어떻게 반영되는가" 같은 예외 처리 자체가 발생하지 않는다.
  덱 저장과 전적이 계정에 묶이는 이상, 계정 없는 플레이는 애초에 저장할 곳이 없으므로 게스트 모드를
  두지 않는 편이 스코프를 좁힌다 (작은 팀 원칙).

### 4.4 이번 스코프에서도 명시적으로 제외되는 것

계정이 생겼다고 해서 계정 관련 기능이 전부 포함되는 것은 아니다. 아래는 이번 마일스톤에서 의도적으로
잘라낸 항목 — 하위 작업자가 "당연히 있겠지"라고 가정하지 않도록 이름을 명시한다.

| 제외 항목 | 이유 |
|---|---|
| 비밀번호 재설정 플로우 | 이메일 발송 인프라(발송 서버, 템플릿, 스팸 방지 등)가 새로 필요한 별도 작업 — 이번 마일스톤 범위 밖. 비밀번호를 잊으면 현재는 새 계정을 만드는 것 외에 방법이 없다. 이는 실사용자 마찰이지만, 작은 팀이 감당 가능한 스코프로 좁히기 위한 의도적 컷이다. 필요해지면 별도로 스펙한다 |
| 이메일 인증(가입 확인 메일) | 같은 이유(이메일 발송 인프라 필요)로 스코프 밖. 오탈자/가짜 이메일로 가입해도 현재는 막지 않는다(로그인 자체는 정상 동작) |
| 표시 이름 변경 기능 | 가입 시 1회 설정 후 고정. 프로필 화면 자체가 없다 |
| 프로필 커스터마이징(아바타, 소개글 등) | 미포함 |
| 친구 목록 / 소셜 기능 | 미포함 |
| 지난 매치 상세 리플레이·관전 | 전적(§6.5)은 결과 메타데이터(상대 이름/승패/날짜)만 저장한다 — 실제 카드 플레이 로그는 저장하지 않으므로 재생 불가 |
| 랭킹/ELO/매치메이킹 강도 조절 | CEO 확정 사항 §1.7 — 승/패 카운트가 매칭에 전혀 영향을 주지 않는다. 매치메이킹은 여전히 임의 방 코드 기반(§6.2)이며 실력 기반 매칭이 아니다 |
| 계정 삭제 / 이메일 변경 / 비밀번호 변경 | 가입·로그인 외의 계정 관리 기능은 없음 |

## 5. 덱 관리

### 5.1 카드 풀

기존 `STARTER_DECK`(2종)과 `REWARD_POOL`(12종)의 구분은 PvP 덱 구성 목적으로는 의미가 없다 — 전체
14종 카드(`CARD_DEFS`의 모든 항목)가 처음부터 동일하게 열려 있는 하나의 풀이다. 언락 조건, 재화, 획득
순서 없음. Strike/Defend를 포함한 모든 카드를 자유롭게 덱에 넣거나 뺄 수 있다.

*(참고: 이 완전 오픈 정책은 추후 진행/언락 시스템이 생기면 재검토 대상 — CEO가 이미 명시한 대로 지금은
범위 밖.)*

### 5.2 덱 구성 규칙 (슬롯 단위로 적용)

| 규칙 | 값 | 근거 |
|---|---|---|
| 덱 최소 장수 | **20장** | 전투당 손패 5장 드로우 기준 최소 4턴은 덱을 다 안 돌게 하려는 하한선. 너무 작은 덱(예: 8장)은 손패가 거의 즉시 순환해 "항상 최적 카드를 들고 있는" 상태가 되어 상대와의 정보 비대칭/운 요소가 지나치게 줄어든다 |
| 덱 최대 장수 | **30장** | 너무 크면 파워 카드(영구 효과)가 매치 내내 안 뽑혀 사실상 죽은 카드가 되는 경우가 늘고, 평균 실제 사용 카드 수가 줄어 매치 체감 길이만 늘어난다. 14종 카드 × 최대 3장(아래) = 42장 여유 안에서 30장 상한이면 "구성 선택"의 의미가 남는다 |
| 카드 1종당 최대 매수 | **3장** | 특정 카드 하나를 몰빵(예: Heavy Slash 20장)해서 일관성으로 밀어붙이는 극단 빌드를 막기 위한 상한. Slay the Spire류 관례상 흔한 값이며, 파워 카드(Iron Skin/Bloodlust/Hoarder) 각 3장까지 허용해도 코스트 1~2·드로우 제한상 한 매치 안에 3장 다 뽑아 전부 발동시키기는 쉽지 않아 과도한 스노우볼로 보지 않음 |
| 저장 슬롯 개수 | **계정당 최대 3개** | CEO 확정 사항 §1.8. 추가 슬롯 구매/해금 없음 — 고정 3개 |
| 슬롯 저장 방식 | 슬롯 편집은 클릭 즉시 저장되는 라이브 편집(§5.5) — "되돌리기"/"저장" 버튼 없음. 계정 서버에 저장되므로 다른 기기로 로그인해도 동일한 3개 덱이 보인다 | 정확한 서버 저장 방식(DB 스키마 등)은 프로그래머 재량 |

편집 화면에서 유효하지 않은 덱(20장 미만)은 "미완성" 상태로 남으며, 매치 큐 진입(§6.1) 시 선택
대상에서 제외된다. 30장 초과/특정 카드 4장째 추가는 애초에 UI에서 막아 시도 자체가 불가능해야 한다
(버튼 비활성화, 클릭해도 무반응 아님 — 비활성 스타일로 눈에 보이게).

### 5.3 덱 이름

- 새 슬롯 생성 시 이름 입력(플레이스홀더 "덱 이름 (선택)", 최대 20자). 비워두면 자동으로 "덱 N"(슬롯
  순번)이 부여된다.
- 이름은 에디터 화면 상단에서 언제든 다시 입력해 바꿀 수 있다 — 클릭/입력 즉시 반영, 별도 저장 버튼
  없음(§5.2의 라이브 편집 원칙과 동일).
- 이름 중복 허용 — 같은 계정 안에 "덱 1"이라는 이름의 슬롯이 두 개 있어도 무방하다. 슬롯은 이름이
  아니라 슬롯 위치(1/2/3)로 구분된다.

### 5.4 새 계정의 기본 상태 & 슬롯 관리 화면

**결정: 신규 계정은 빈 3슬롯이 아니라 슬롯 1에 24장짜리 기본 스타터 덱이 미리 채워진 상태로
시작한다.**

| 카드 | 매수 | 카드 | 매수 |
|---|---|---|---|
| Strike | 3 | Quick Guard | 2 |
| Defend | 3 | Second Wind | 2 |
| Heavy Slash | 2 | Adrenaline | 1 |
| Twin Strike | 2 | Fortify | 2 |
| Piercing Strike | 2 | Iron Skin | 1 |
| Execute | 1 | Bloodlust | 1 |
| Reckless Swing | 1 | Hoarder | 1 |

(3+3+2+2+2+1+1+2+2+1+2+1+1+1 = 24장, 14종 카드를 최소 1장씩 포함, §5.2 규칙을 모두 만족)

- 슬롯 이름은 "스타터 덱"으로 고정 표기(플레이어가 나중에 이름을 바꾸는 것은 자유). 슬롯 2, 3은
  비워둔 채로 시작한다.
- *근거*: 계정이 생기면서 가입 스텝(이메일/비밀번호/표시 이름 입력)이 이미 하나 늘었다. 그 직후 "먼저
  20장짜리 덱을 처음부터 만들어야 플레이할 수 있음"까지 강제하면 첫 플레이까지의 마찰이 두 배로
  쌓인다. "편집 한 번 안 해도 바로 플레이할 수 있어야 한다"는 이 스펙의 원래 원칙(구버전 §4.3)은
  계정 도입 이후에도 그대로 유효하며, 오히려 더 중요해졌다. 슬롯 2·3을 비워두면 "기본 제공 덱"과
  "직접 만든 덱"이 한눈에 구분된다.
  - 대안으로 고려했던 "계정당 0개로 시작 + 첫 플레이 전 덱 생성 강제"는 기각한다 — 강제 자체가
    나쁜 게 아니라, 이미 잘 만들어둔 기본 덱(구버전에서 검증된 24장 구성)이 있는데 굳이 매 계정마다
    처음부터 다시 만들게 할 이유가 없다.

메인 메뉴 → "덱 관리" 진입 시 보이는 **슬롯 목록 화면**:

- 3개의 슬롯을 카드형 타일로 나란히 표시.
- **채워진 슬롯**: 덱 이름, 카드 매수(`N/30`), 유효/무효 뱃지(20장 미만이면 "미완성" 경고 뱃지),
  "편집" 버튼, "삭제" 버튼.
- **빈 슬롯**: "+ 새 덱 만들기" 플레이스홀더 타일. 클릭 시 이름 입력(§5.3) 후 바로 해당 슬롯의
  에디터 화면(§5.5)으로 진입.
- **삭제**: 확인 다이얼로그("이 덱을 삭제하시겠습니까? 되돌릴 수 없습니다" / 취소·삭제) 후 즉시
  슬롯이 빈 상태로 바뀐다. 삭제된 덱 내용은 복구 불가.
- **편집**: 기존 카드 구성을 그대로 불러온 상태로 §5.5 에디터 화면 진입.

### 5.5 에디터 UI/UX (슬롯 단위)

기존 카드 컴포넌트(`art-direction.md` §3, 132×184px 카드 프레임)를 그대로 재사용한다 — 새 카드 비주얼
언어를 만들지 않는다.

- **레이아웃**: 상단/좌측에 "카드 풀" 그리드(14종 전부 항상 노출, 정렬은 타입별: Attack → Skill →
  Power, 기존 GDD §6.2 순서 그대로), 하단/우측에 "이 덱" 목록. 화면 최상단에 편집 중인 슬롯의 이름
  입력 필드(§5.3).
- **카드 풀 타일**: 각 카드 위에 현재 보유 매수 배지 (`n/3`, 3장 다 채우면 배지가 타입 컬러로 꽉 참 +
  타일 살짝 어둡게 처리해 "더 못 넣음"을 시각적으로 표시). 타일 클릭 = 해당 카드 1장 덱에 추가 (풀·최대
  매수 조건 안 걸리면 즉시 반영, 애니메이션 없이 카운터만 갱신 — 배틀 화면처럼 무거운 연출 불필요).
  최대 매수(3) 또는 최대 덱 장수(30) 도달 시 타일이 비활성 스타일(불투명도 낮춤)로 바뀌고 클릭 무반응.
- **이 덱 목록**: 카드 풀 타일보다 작은 리스트 행(코스트 배지 + 이름 + 보유 매수 + `-` 버튼)으로 표시 —
  풀 그리드와 시각적으로 구분되게 해 "브라우징 영역"과 "구성 결과 영역"이 한눈에 나뉘어야 한다. `-` 클릭
  = 해당 카드 1장 제거.
- **상단 카운터**: "덱: N/30 (최소 20)" 상시 표시. N < 20이면 카운터가 경고색(`--crimson`)으로 바뀌고
  하단 안내 문구 "최소 20장이 필요합니다" 노출.
- **되돌리기 버튼 없음** — 매 클릭이 즉시 반영/저장되는 라이브 편집 방식이므로 "저장" 버튼도 없음. 화면
  상단 "완료" 버튼을 누르면 **덱 관리 슬롯 목록 화면(§5.4)으로 돌아간다** (덱이 20장 미만이어도 편집
  화면을 나갈 수는 있음 — 다만 그 상태로는 §6.1에서 매치용 덱으로 선택할 수 없고 "미완성" 뱃지가 붙음).

## 6. 매치 플로우

### 6.1 매치 전 덱 선택

메인 메뉴에서 "플레이"를 누르면 로비로 바로 가지 않고 **덱 선택 화면**이 먼저 뜬다.

- 계정에 저장된 3개 슬롯 중 **유효한(20~30장) 덱만** 선택 가능한 카드로 표시된다. 무효 슬롯
  (미완성이거나 빈 슬롯)은 비활성 스타일 + "미완성" 뱃지로 표시되고 선택할 수 없다.
- **유효한 덱이 하나도 없는 경우** (예: 스타터 덱까지 지워버린 계정): "플레이" 버튼 자체가 **메인
  메뉴 단계에서 미리 비활성화**되고, 안내 문구 "매치를 시작하려면 유효한 덱(20~30장)이 하나 이상
  있어야 합니다" + "덱 관리로 이동" 버튼을 노출한다. 덱 선택 화면까지 갔다가 막히는 것보다 메인
  메뉴에서 미리 걸러 불필요한 화면 전환을 줄인다.
- 덱을 고르면 **그 덱이 이번 매치에 고정 사용된다** — 로비 진입 이후에는 덱을 바꿀 수 없다(프로듀서
  플랜 0.4가 우려한 "로비 중간에 편집 못 하게 갇히는" 문제는, 덱 선택이 애초에 로비 진입 전 별도
  화면에서 끝나도록 순서를 고정해 해결한다). 다른 덱으로 바꾸고 싶으면 로비를 나가 덱 선택 화면으로
  돌아가야 한다.
- 마지막으로 선택했던 덱을 기억해 다음 플레이 시 기본 하이라이트로 미리 선택해두는 것은 편의 기능으로
  권장하지만 필수는 아니다(프로그래머 재량).

### 6.2 방 생성/참가 UX

덱 선택(§6.1) 이후 두 개의 선택지: **방 만들기** / **코드로 참가하기**.

- **방 만들기**: 클릭 즉시 방 코드가 생성되어 화면 중앙에 크게 표시 (영숫자 6자리 권장, 예: `A3F9K2` —
  정확한 코드 생성 로직/충돌 처리는 프로그래머 재량). 코드 옆에 "복사" 버튼. 아래에 "상대를 기다리는
  중..." 문구 + 로딩 인디케이터. 상대가 같은 코드로 참가하면 화면에 **상대의 표시 이름**이 나타나고
  (§4.1 — 이메일이 아니라 표시 이름), 자동으로 다음 단계(§6.3)로 전환 — 별도 확인 버튼 없음.
- **코드로 참가하기**: 코드 입력 필드(자동 대문자 변환, 6자리 채워지면 "참가" 버튼 활성화) + "참가"
  버튼. 잘못된 코드/존재하지 않는 방/이미 꽉 찬 방인 경우 인라인 에러 메시지 표시하고 입력 필드는
  유지 (재입력 가능). 참가에 성공하면 마찬가지로 상대의 표시 이름이 화면에 나타난다.
- 이 화면에서 "뒤로" 버튼으로 언제든 덱 선택 화면으로 복귀 가능 (방 만들기로 대기 중이었다면 방은
  폐기됨).

### 6.3 매치 시작 시퀀스

양쪽이 연결되면 자동으로 진행 (별도 "준비" 버튼 없음 — 덱은 이미 §6.1에서 확정됐으므로 추가로 확인할
것이 없다):

1. **선공 결정**: 무작위 동전 던지기. 화면에 짧게(약 1.5초) "선공 정하는 중..." 연출 후 결과 표시
   ("먼저 시작합니다" / "상대가 먼저 시작합니다").
2. **셔플/드로우**: 각 클라이언트가 자신의 덱을 로컬에서 셔플 (기존 `shuffle()` 로직 재사용, 상대
   덱 내용을 알 필요도 없고 동기화할 필요도 없음 — 각자 자기 패만 진짜로 안다는 원칙은 프로듀서 플랜
   1.3의 권장 방향과 일치).
3. **오프닝 드로우**: 선공 플레이어는 5장, **후공 플레이어는 6장** 드로우.
   - *근거*: 선공은 상대보다 한 턴 먼저 마나/카드를 쓸 수 있는 명백한 템포 우위가 있다. 카드 게임에서
     흔한 보정(예: 후공 보너스 카드)을 가장 단순한 형태로 적용 — 후공 첫 턴에만 카드 1장을 더 준다.
     장기 밸런스 패치가 아니라 "동전 던지기 결과가 승패를 과하게 좌우하지 않게" 하는 최소한의 안전장치.
4. **배틀 화면 진입**, 선공 플레이어의 턴 타이머(24초, §7.3)가 시작된다.

### 6.4 승패 조건 & 매치 종료 화면

- **승리 조건**: 상대 HP가 0 이하가 되는 즉시 매치 종료 (기존 `dealDamageToEnemy`/`winCombat` 로직과
  동일한 즉시 판정 — 턴이 끝날 때까지 기다리지 않음).
- **덱 소진은 패배 조건이 아니다**: 드로우 더미와 버린 더미가 모두 비면 그 턴은 그냥 카드를 못 뽑을 뿐 —
  기존 `drawCards()`의 "둘 다 비었으면 조용히 중단" 동작을 그대로 유지. 최소 덱 장수 20장 규칙(§5.2)
  덕에 실전에서 자주 발생하지는 않지만, 발생해도 게임 종료 조건이 아님을 명시해 프로그래머가 별도로
  "덱 소진 패배" 로직을 만들지 않도록 한다.
- **종료 화면 문구 3종**:
  | 상황 | 문구 |
  |---|---|
  | 상대 HP 0 | "승리!" |
  | 내 HP 0 | "패배" |
  | 상대 접속 끊김으로 기권 처리 (§8) | "승리! (상대방 접속 종료)" |
- 종료 화면 버튼: **"다시 플레이"**(덱 선택 화면으로 복귀, §6.1부터 다시 시작) / **"메인 메뉴"**(메인
  메뉴 화면으로).
- **매치 종료 시 결과가 양쪽 계정의 전적에 자동 기록된다 (§6.5)**: 승자는 자신의 전적에 1승, 패자는
  1패가 추가된다. 기권승도 승리로 카운트되고(패배한 쪽은 패배로 기록), 상대가 재접속하지 못해 §8.2의
  45초 자동 기권으로 종료된 경우도 동일하게 기록된다.

### 6.5 전적 (Match History)

- **어디서 보는가**: 메인 메뉴에 "전적" 버튼을 덱 관리/플레이와 나란히 추가한다. 클릭하면 전적 화면으로
  이동.
- **화면 상단**: "총 N승 M패" 집계 수치를 크게 표시한다. 이 수치는 별도로 관리하는 카운터가 아니라
  아래 리스트에서 계산되는 파생값이다(정확한 계산/캐싱 방식은 프로그래머 재량).
- **화면 본문**: 매치 결과 리스트, 최신 매치가 맨 위. 각 행에 표시하는 정보:
  - 상대의 표시 이름
  - 결과: "승" / "패", 단 기권승인 경우 "승 (기권)"으로 구분 표기 — 승/패 집계에는 정상 승리와 동일하게
    승으로 카운트되지만, 플레이어가 실제로 끝까지 겨뤄서 이긴 것인지 투명하게 구분해서 보여준다.
  - 날짜: `YYYY-MM-DD` 형식만 표시 — 정확한 시각까지는 표시하지 않는다(스캔하기 쉬운 최소 정보 유지).
- **범위**: 최근 100경기까지만 화면에 표시한다. 그 이상의 과거 이력은 서버에 계속 쌓여도 무방하지만,
  화면에는 페이지네이션/무한스크롤 없이 최근 100건만 노출한다 — 스코프를 좁히기 위한 의도적 컷.
- 리스트가 비어 있으면(첫 매치 전) "아직 플레이한 매치가 없습니다" 안내 문구.
- **왜 "카운트만"이 아니라 "리스트"를 스펙에 넣었는가**: 승/패를 세려면 어차피 매치 결과를 어딘가
  영속 저장해야 하므로, 카운터 하나만 저장하는 것과 개별 매치 리스트를 저장하는 것 사이의 구현 비용
  차이는 거의 없다. 리스트를 저장하면 상단의 승/패 카운트는 자동으로 그 리스트의 파생값이 되고,
  플레이어 입장에서도 "누구를 상대로 이기고 졌는지" 확인할 수 있는 정보가 사실상 공짜로 따라온다.
  반대로 카운터만 저장하면 나중에 리스트가 필요해졌을 때 과거 데이터를 소급할 수 없다(카운터는 개별
  매치 정보를 버리는 집계이므로). CEO 요구사항(§1.7)이 명시한 "ELO/랭킹은 없음"이라는 선은 그대로
  지키면서, 작은 팀 원칙에 어긋나지 않는 선에서 더 미래 호환적인 쪽을 택했다.

## 7. PvP 턴 구조

### 7.1 플레이어 상태 값 — 대칭 적용

기존 `PLAYER_START`를 양쪽 플레이어에 동일하게 적용한다 (한쪽만 다르게 튜닝할 근거가 없음 — 적 전용
수치가 애초에 없었으므로 그대로 상속):

| 항목 | 값 |
|---|---|
| 시작 HP | 50 / 50 |
| 턴당 마나 | 3 / 3 |
| 턴당 드로우 | 5장 (단, 후공 첫 턴만 6장 — §6.3) |
| 방어도(Block) 규칙 | 기존과 동일 — 상대 턴이 끝나고 내 다음 턴 시작 전에 초기화 |
| 파워 카드 효과 | 기존과 동일, "런" → "이번 매치" 동안 지속 (§2 참고) |

### 7.2 턴 교대 & 정보 공개 범위

- **엄격한 순서 교대**: 내 턴 → 상대 턴 → 내 턴 ... 동시 행동 없음 (기존 싱글플레이어 엔진의 턴 구조를
  그대로 인간 대 인간으로 확장).
- **내 손패**: 전부 보임 (카드 앞면, 기존과 동일).
- **상대 손패**: 카드 앞면/정체 절대 비공개. 카드 뒷면 디자인의 작은 카드 다발로 매수만 표시 (예: 상대
  영역에 "카드 다발 아이콘 × N" — 실제 카드 뒷면 비주얼은 아트 디렉션 후속 작업, §9 참고). 상대가
  카드를 낼 때마다 그 카드가 실시간으로 공개되며 플레이되는 연출은 그대로 노출 (낸 카드 자체는 공개
  정보이므로 숨기지 않음 — 숨기는 것은 "아직 안 낸 손패"뿐).
- **상대 표시 이름**: 배틀 화면 상대 패널 상단에 상대의 표시 이름이 항상 노출된다 (계정 도입 전에는
  상대가 완전히 익명이었으나, 이제 계정이 있으므로 누구와 겨루는지 식별 가능해야 한다 — 이메일은
  §4.1에 명시한 대로 어디에도 노출하지 않는다).
- **상대 보드 상태**: HP/최대HP, 방어도, 마나(현재/최대), 덱 더미 장수, 버린 더미 장수는 전부 실시간
  공개 (기존 GDD의 "정보를 숨기지 않는 것이 장르 핵심 재미" 원칙을 공개 정보 범위에서는 유지).
- **의도(intent) 예고 없음**: §2에서 명시한 대로 완전 제거. 상대 영역에는 더 이상 "다음 행동 예고
  배지"가 없다 — 실제 상대가 무엇을 낼지는 그들이 카드를 내는 순간에만 알 수 있다.
- **내 턴이 아닐 때**: 내 손패 카드는 선택 불가(비활성 스타일), 화면 상단에 "상대 턴" 표시. 기존 엔진의
  `turnBusy` 입력 잠금 개념을 "상대 턴 동안 항상 켜짐"으로 그대로 매핑 가능.

### 7.3 턴 타이머 (24초)

- **적용 범위**: 드로우 페이즈가 끝나고 카드를 낼 수 있게 된 시점부터 24초. 드로우 애니메이션 자체는
  타이머에 포함하지 않음 (플레이어가 실제로 행동할 수 있는 시간만 24초여야 공정함).
- **UI**: 활성 플레이어의 턴 타이머는 **양쪽 화면에 모두** 숫자 카운트다운으로 노출 (마나 게이지 근처,
  "End Turn" 버튼 옆). 상대도 내 남은 시간을 볼 수 있어야 함 — 서로의 타이밍 압박을 읽는 것도 대전
  게임의 정보 중 하나로 취급.
  - 10초 초과: 기본 잉크 컬러(`--ink`)
  - 10초 이하: 경고색(`--crimson`)로 전환 + 은은한 pulse (art-direction.md §7의 기존 pulse 애니메이션
    패턴 재사용, `prefers-reduced-motion` 존중)
  - 사운드 큐 없음 (GDD §10 "사운드/BGM 스코프 제외" 원칙 유지)
- **타임아웃 시 동작 (명확히 정의)**:
  1. 만약 카드를 선택해 타겟 대기 중(`selected` 상태)이었다면, 그 카드는 **미발동 상태로 손패에 되돌아간다**
     (마나 소모 없음, 효과 없음 — `resolveCard`가 애초에 마나를 타겟 확정 시점에 차감하므로 취소해도
     되돌릴 상태가 없음).
  2. 그 즉시 **"End Turn"을 직접 누른 것과 완전히 동일한 처리**가 실행된다: 남은 손패 전량 버림, 마나는
     다음 내 턴에 그대로 리셋, 상대 턴으로 전환.
  3. 이미 낸 카드의 효과는 그대로 유지된다 — "타임아웃 = 이번 턴에 한 것까지만 인정하고 강제 종료"이지
     되돌리기가 아니다.
  4. 상대 화면에는 "시간 초과로 턴 종료"라는 별도 문구 없이, 그냥 정상적인 턴 종료와 동일하게 보인다
     (구분할 필요 없음 — 결과가 동일하므로).

### 7.4 파워 카드/의도 시스템 처리 요약

- Iron Skin / Bloodlust / Hoarder: 기존 수치·동작 그대로, "이번 매치 동안" 누적.
- 의도 시스템: §2, §7.2에 명시한 대로 완전 삭제. `describeIntent()`에 대응하는 PvP측 개념은 없음.

## 8. 접속 끊김 / 기권 처리

### 8.1 유예 시간: 45초

**연결이 끊긴 순간부터 45초 안에 복구되지 않으면 자동 기권 처리한다.**

*근거*:
- 턴 타이머(24초)보다 확실히 길어야 한다 — 그렇지 않으면 "네트워크가 잠깐 끊겼다 바로 돌아온" 경우조차
  타이머 관련 혼란을 만든다.
- 30초는 모바일에서 화면 잠김/와이파이 전환처럼 흔한 일시적 단절을 감당하기엔 살짝 빠듯하다 (탭을 다시
  켜고 앱이 재연결을 시도하는 데만 몇 초에서 10여 초가 걸릴 수 있음).
- 60초는 반대로 연결이 살아있는 상대방을 아무 할 일 없이 너무 오래 세워두는 쪽이다 — 이 게임의 전투
  하나는 원래 몇 분 내로 끝나는 것을 목표로 하는데(GDD §1), 그 안에서 1분 가까이 완전히 멈춰서는
  경험은 "고장난 게임"처럼 느껴질 위험이 크다.
- **45초**로 절충 — 흔한 일시적 단절(화면 잠금 해제, 와이파이 재연결, 탭 크래시 후 즉시 재접속)은
  커버하면서, 상대를 무한정 기다리게 하지는 않는다.
- 접속 끊김은 턴 소유자와 무관하게(내 턴/상대 턴 어느 쪽이든) 동일하게 적용된다.

### 8.2 접속 끊김 발생 시 처리

- **턴 타이머는 즉시 일시정지된다.** 24초 턴 타이머와 45초 기권 유예 타이머가 동시에 따로 흘러가는
  상황은 만들지 않는다 — 접속이 끊긴 순간 게임 시계 자체가 멈추고, 오직 45초 기권 카운트다운만 진행된다.
  복구되면 턴 타이머는 멈췄던 지점부터 다시 흐른다.
- **연결이 유지된 플레이어가 보는 화면**: 현재 보드 상태(양쪽 HP/마나/방어도 등) 위에 반투명 오버레이
  배너 — "상대방의 연결이 끊겼습니다. 재접속을 기다리는 중... (남은 시간: N초)". 이 배너가 떠 있는 동안
  자신의 카드도 선택/플레이 불가 (게임이 완전히 정지 상태이므로).
  - 이 화면에 **"기권승 처리하기"** 버튼을 두되, 접속 끊김 감지 후 **최소 10초가 지나야 활성화**된다.
    이유: 아주 짧은 순간의 렉/버퍼링만으로 상대가 즉시 기권패를 당하는 상황(오탐/그리핑 여지)을 막기
    위한 최소 유예. 10초가 지나면 이 버튼으로 45초를 다 기다리지 않고도 스스로 즉시 종료를 선택할 수
    있다.
- **45초가 지나도 복구되지 않으면**: 자동으로 기권 처리, 연결 유지 플레이어 화면은 §6.4의 "승리!
  (상대방 접속 종료)" 종료 화면으로 전환. 이 결과 역시 §6.4에 명시한 대로 양쪽 전적에 자동 기록된다.

### 8.3 재접속 범위 (명시적 한계)

- **지원 범위**: 같은 탭/세션이 살아있는 상태에서 네트워크 연결만 일시적으로 끊겼다가 45초 안에 다시
  이어지는 경우 — 이 경우는 클라이언트 쪽 게임 상태(`state.js`에 해당하는 값들, 내 손패/덱 순서 등)가
  애초에 사라진 적이 없으므로 "재접속 = 통신 재개"만으로 매치가 자연스럽게 이어진다.
- **지원하지 않음 (범위 밖으로 명시)**: 탭을 닫았다 새로 열거나 페이지를 새로고침한 경우. 이 경우 로컬
  게임 상태가 전부 사라지므로, 다시 들어와도 진행 중이던 매치를 "재개"시키지 않는다 — 45초 안에 같은
  방 코드로 재입장하더라도 매치는 이미 끝난 것으로 간주하거나(늦게 들어온 경우) 진행 중인 매치에
  끼어들 수 없다. 이런 경우의 실제 화면 처리(예: "이미 종료된 매치입니다" 안내 후 메인 메뉴로)는
  프로그래머 재량이되, **완전한 상태 재동기화(hidden 정보까지 포함한 매치 재개)는 이번 MVP 스코프에
  포함하지 않는다**는 것만 이 문서에서 확정한다. 이는 온라인 PvP 자체가 이미 이 프로젝트 최대 난이도
  작업(`online-pvp-plan.md` 서두)이라는 점을 고려해, 작은 팀 원칙("완결 가능한 코어 루프 우선")에 따라
  의도적으로 잘라낸 범위다. 필요해지면 후속 마일스톤에서 별도로 스펙한다.

## 9. 후속 작업 필요 항목 (이 스펙이 새로 만드는 아트/문서 부채)

프로그래머/아티스트가 이 스펙을 구현하면서 마주칠, 이 문서가 수치/동작은 정의했지만 비주얼은 정의하지
않은 항목들 — 아티스트가 `art-direction.md`에 후속으로 추가해야 함:

- 상대 손패의 "카드 뒷면" 비주얼 (§7.2) — 지금까지 카드 뒷면 디자인이 존재한 적이 없음.
- 상대 보드 영역 레이아웃 — 기존 "적 영역"(포트레이트+실루엣+의도 배지, art-direction.md §5-6)은 스크립트
  괴물 전용 디자인이라 인간 상대에게는 맞지 않음. HP/방어도/마나/손패 매수/덱-버림더미 카운터 + **상대
  표시 이름**을 담은 새 "상대 플레이어 패널" 레이아웃 필요.
- 방 코드 화면, 로비 대기 화면, 덱 관리(슬롯 목록 + 슬롯 에디터) 화면의 실제 비주얼 — 이 문서는 배치/동작만
  정의했고 톤(오컬트 장부 스타일)에 맞는 구체적 목업은 아직 없음.
- **로그인/회원가입 화면** 비주얼 — 이 프로젝트에 존재한 적 없는 완전히 새로운 화면(§4).
- **전적 화면** 비주얼 — 승/패 집계 + 매치 리스트 레이아웃(§6.5).
- `onboarding.md` §2 항목 4(의도 아이콘 설명)의 개정 — §2에서 플래그한 대로 별도 기획 작업.

## 10. 완료 기준 (Definition of Done)

- 방 만들기/코드로 참가하기로 두 클라이언트가 정상적으로 매칭되어 매치가 시작된다.
- 이메일/비밀번호로 회원가입·로그인이 정상 동작하고, 상대에게는 항상 표시 이름만 노출되며 이메일은
  로비/배틀/전적 어디에도 노출되지 않는다.
- 비로그인 상태에서는 로그인/회원가입 화면과 How to Play 외의 어떤 화면에도 진입할 수 없다.
- 신규 계정은 슬롯 1에 24장 스타터 덱이 자동으로 채워진 채 시작하고, 슬롯 2·3은 비어 있다.
- 계정당 최대 3개의 덱 슬롯을 생성/편집/삭제할 수 있고, 덱 에디터에서 20~30장·카드당 최대 3장 규칙이
  실제로 강제된다(규칙 위반 시 UI에서 애초에 불가능).
- "플레이" 진입 시 유효한(20~30장) 슬롯 중 하나를 선택해야만 로비로 진입할 수 있고, 유효한 슬롯이
  하나도 없으면 메인 메뉴에서 "플레이" 버튼 자체가 비활성화된다.
- 선공 무작위 결정 + 후공 첫 턴 6장 드로우가 매 매치 정상 동작한다.
- 내 손패는 항상 보이고, 상대 손패는 매수만 보이고 카드가 실제 플레이될 때만 정체가 드러난다. 상대
  패널에는 항상 상대의 표시 이름이 보인다.
- 24초 턴 타이머가 양쪽 화면에 동일하게 보이고, 타임아웃 시 §7.3의 동작(미해결 카드 취소 + 자동 턴
  종료)이 정확히 실행된다.
- 접속 끊김 발생 시 턴 타이머가 멈추고 45초 기권 유예가 시작되며, 10초 후 상대방이 "기권승 처리하기"를
  쓸 수 있고, 45초 경과 시 자동 기권 처리된다.
- 상대 HP 0 → 즉시 매치 종료 + 승리 화면, 내 HP 0 → 패배 화면, 기권 처리 → 기권승 화면이 각각 정확한
  문구로 표시된다.
- 매치가 끝날 때마다(정상 종료·기권승 포함) 양쪽 계정의 전적에 결과가 자동 기록되고, 전적 화면에서
  총 승/패 수와 최근 매치 리스트(상대 표시 이름/결과/날짜, 최대 100건)를 확인할 수 있다.
- 옛 던전 런 화면(보상 선택, 휴식, 다중 전투 진행)이 어디에서도 노출되지 않는다 — 로그인 이후 메인
  메뉴에 모드 선택 없이 "덱 관리"/"전적"/"플레이" 세 개만 있다.
